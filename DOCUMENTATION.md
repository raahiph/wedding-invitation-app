## Overview

A private wedding invitation web app. Guests verify their identity via mobile number, view the invitation, RSVP, and share/view photos. An admin panel manages guests, settings, and the photo gallery.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | Laravel 12 (PHP 8.2+) |
| Database | MySQL (local dev), MySQL (production) |
| Storage | Local (thumbnails) + Dropbox (originals) |
| Sessions | File driver |
| Assets | Vanilla CSS/JS, no build step |
| Fonts | Montserrat, BrittanySignature (self-hosted) |
| Image processing | intervention/image-laravel |
| Dropbox | spatie/flysystem-dropbox + spatie/dropbox-api |

## Local Setup

### Requirements

- PHP 8.2+
- Composer
- MySQL
- XAMPP (or equivalent)

### Steps

```bash
# 1. Clone or copy the project
cd c:/xampp/htdocs
# project folder: invitation-app/

# 2. Install PHP dependencies
cd invitation-app
composer install

# 3. Copy and configure environment
cp .env.example .env   # or edit .env directly
php artisan key:generate

# 4. Create the MySQL database
# In phpMyAdmin or MySQL CLI:
CREATE DATABASE `invitation-app`;
CREATE USER 'invitation-app'@'localhost' IDENTIFIED BY 'invitation-app';
GRANT ALL ON `invitation-app`.* TO 'invitation-app'@'localhost';

# 5. Run migrations
php artisan migrate

# 6. Create the storage symlink (for serving thumbnails)
php artisan storage:link

# 7. Start the server (XAMPP Apache, or)
php artisan serve
```

## Database

### Tables

#### `guests`
Stores each invited guest.

| Column | Type | Notes |
|---|---|---|
| id | int | Primary key |
| mobile | varchar(20) | Unique. Used for login verification |
| name | varchar(120) | Guest's display name |
| notes | varchar(255) | Admin notes |
| side | enum | `groom`, `bride`, `other` |
| attends_ceremony | boolean | Whether guest attends the ceremony (not just reception) |
| session | tinyint | Reception session: `1` or `2`. Null = ceremony guest |
| created_at / updated_at | timestamp | |

#### `rsvps`
One-to-one with guests. Created when a guest submits the RSVP form.

| Column | Type | Notes |
|---|---|---|
| id | int | Primary key |
| guest_id | int | FK → guests.id (unique, cascades on delete) |
| full_name | varchar(120) | Nullable |
| attending | boolean | Default true |
| plus_ones | tinyint | Number of additional attendees |
| dietary | varchar(255) | Dietary requirements |

#### `settings`
Key-value store for admin-configurable wedding details.

| Column | Type | Notes |
|---|---|---|
| key | varchar | Primary key |
| value | text | |

No timestamps. Merged with `config/wedding.php` defaults at runtime.

#### `photos`
Uploaded guest photos.

| Column | Type | Notes |
|---|---|---|
| id | int | Primary key |
| guest_id | int | FK → guests.id. Nullable (anonymous uploads) |
| dropbox_path | varchar | Path to original file on Dropbox |
| thumb_path | varchar | Path to local 1200px thumbnail |
| approved | boolean | Default true |
| created_at / updated_at | timestamp | |

## Dropbox Setup

Photos are uploaded to Dropbox for permanent storage. Thumbnails are also saved locally for fast display.

### Step 1 — Create a Dropbox App

1. Go to [https://www.dropbox.com/developers/apps](https://www.dropbox.com/developers/apps)
2. Click **Create app**
3. Choose:
   - API: **Scoped access**
   - Access type: **Full Dropbox** (or App folder)
   - Name: anything (e.g. `wedding-gallery`)

### Step 2 — Set Permissions

In your app → **Permissions** tab, enable:

- `files.content.write`
- `files.content.read`

Click **Submit** to save.

### Step 3 — Generate a Refresh Token

Short-lived tokens (from the App Console) expire in 4 hours. Use a refresh token instead — it never expires.

**In your browser**, open this URL (replace `APP_KEY`):
```
https://www.dropbox.com/oauth2/authorize?client_id=APP_KEY&response_type=code&token_access_type=offline
```

Click **Allow** and copy the authorization code shown.

**In your terminal**, exchange it for a refresh token (replace all placeholders):
```bash
curl -X POST https://api.dropboxapi.com/oauth2/token \
  -d code=YOUR_AUTHORIZATION_CODE \
  -d grant_type=authorization_code \
  -d client_id=YOUR_APP_KEY \
  -d client_secret=YOUR_APP_SECRET
```

The JSON response will contain `refresh_token`. Copy it.

### Step 4 — Update `.env`

```env
DROPBOX_APP_KEY=your_app_key
DROPBOX_APP_SECRET=your_app_secret
DROPBOX_REFRESH_TOKEN=your_refresh_token
DROPBOX_APP_FOLDER=/Wedding-Gallery   # folder path inside Dropbox
```

Then clear config cache:
```bash
php artisan config:clear
php artisan cache:clear
```

### How It Works

- On each upload, the app exchanges the refresh token for a short-lived access token (valid 4 hours) via the Dropbox OAuth2 endpoint
- The access token is **cached for 3.5 hours** — so the exchange only happens occasionally, not on every upload
- The refresh token is permanent and never needs to be regenerated
- Photo originals are uploaded to Dropbox at `/{name-slug}_{uuid}_original.{ext}`
- A 1200px JPEG thumbnail is saved locally to `storage/app/public/gallery/` for fast display

## Admin Panel

Access at `/admin/login`.

Credentials are set in `.env`:
```env
ADMIN_USER=admin
ADMIN_PASS=your_password
```

### Dashboard — `/admin/`

- Guest list with RSVP status, session, side
- Stats: total guests, RSVPs submitted, attending count
- Add / remove guests
- Toggle ceremony attendance and session assignment per guest
- Toggle RSVP-only mode (hides the full invitation)

### Gallery — `/admin/gallery`

- Grid view of all uploaded photos
- Single delete button per photo
- **Bulk delete**: long-press (500ms) any photo card to enter select mode, then tap additional cards and click "Delete selected"
- **Select all** checkbox for quick bulk deletion

### Settings — `/admin/settings`

Configure all wedding details: names, date/time, venue, dress code, RSVP deadline, map URL, session times. Changes are saved to the `settings` table and override `config/wedding.php` defaults immediately.

## Guest Flow

### 1. Verification — `/gate`

Guests enter their mobile number. The number is normalised (non-digits stripped) and looked up in the `guests` table. If found, a session is created:

```
session('guest_id') = guest.id
session('guest_name') = guest.name
```

If not found, an error is shown: *"Your number wasn't found on our guest list."*

### 2. Invitation — `/`

Full scrolling invitation page showing:
- Hero with names and event details
- Quranic ayah
- Date, time, venue, dress code cards
- Venue card links to Google Maps (if map URL is set in admin settings)
- Programme timeline (ceremony guests only — guests with `attends_ceremony = true`)
- RSVP form
- Photo gallery preview strip (latest 8 approved photos)

### 3. RSVP — `POST /rsvp`

RSVP is submitted inline on the invitation page via fetch. Creates or updates an `rsvp` record for the guest.

### 4. Gallery — `/gallery`

Full photo gallery (requires sign-in). Masonry grid with lightbox.

### 5. Photo Upload — `/upload`

Public page (no sign-in required). Guests scan a QR code at the venue to upload photos directly. Supports multiple files, drag & drop, per-file progress bars.

## Photo Gallery

### Guest Upload Page — `/upload`

- No authentication required — designed for a QR code at the venue
- Accepts JPG, PNG, WEBP up to 30 MB each
- Multiple file selection and drag & drop supported
- Per-file progress bar during upload
- After all uploads complete, shows a "thank you" confirmation
- "View gallery" link redirects to `/gallery` (requires sign-in)

### Gallery Page — `/gallery`

- Requires guest sign-in
- Masonry grid layout (4 columns desktop → 2 columns mobile)
- Lightbox with keyboard navigation (← → Escape), touch swipe, and counter
- Lightbox controls (close, prev, next) are fixed to viewport edges; float over image on narrow screens
- Polls for new photos every 15 seconds
- Photos uploaded during the session appear instantly (prepended to grid)

### Upload Flow

1. Guest selects files
2. Each file is uploaded via XHR `POST /gallery`
3. Server resizes to 1200px JPEG thumbnail, saves locally
4. Server uploads original to Dropbox
5. `Photo` record created in database with both paths
6. JSON response `{ ok: true, photo: { id, thumb_url } }` returned
7. New photo card prepended to gallery grid

## Deploying to Shared Hosting

### One-time Setup (SSH)

```bash
# SSH into your hosting account
ssh user@yourdomain.com

# Clone repo outside public_html
git clone https://github.com/you/repo.git ~/invitation-app
cd ~/invitation-app

# Install dependencies
composer install --no-dev --optimize-autoloader

# Set up environment
cp .env.example .env
nano .env   # fill in DB, Dropbox, admin credentials, APP_URL

# Generate app key
php artisan key:generate

# Run migrations
php artisan migrate --force

# Create storage symlink
php artisan storage:link
```

### Point Domain to Laravel's `public/` folder

In cPanel → **Domains** → set the document root to:
```
/home/youruser/invitation-app/public
```

### Deploying Updates

```bash
ssh user@yourdomain.com
cd ~/invitation-app
git pull
composer install --no-dev --optimize-autoloader
php artisan config:clear
php artisan migrate --force
```

### Important `.env` Changes for Production

```env
APP_ENV=production
APP_DEBUG=false
APP_URL=https://yourdomain.com
CACHE_STORE=file        # shared hosting may not have database cache tables
SESSION_DRIVER=file
QUEUE_CONNECTION=sync   # no persistent workers on shared hosting
```

### Things That Don't Work on Shared Hosting

- Persistent queue workers (`QUEUE_CONNECTION=sync` handles this)
- Websockets
- Cron jobs longer than a few seconds

This app does not use any of these, so shared hosting works fine.
